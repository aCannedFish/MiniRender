# 资产导出

A4.2a 增加 `save_obj`，并让 `save_scene` 自动写出 `source` 为空的生成网格。核心不依赖 Qt；A4.2b 将在后台调用这些接口。已有原始 OBJ 不随几何操作改写。

## OBJ 格式

每个共享位置写为一个 `v`，包括未使用的位置。每个面角分别写出 `vt` 和 `vn`，三角形通过独立的 `v/vt/vn` 索引引用它们。这样保留位置连接、UV 接缝和法线方向，不会把面角数据展开成独立几何位置。法线以单位方向导出，与 OBJ 读取器一致。

输出使用经典数字格式和 float 的 `max_digits10` 精度，避免系统小数点设置影响文件，并保证位置与 UV 的 float 往返。文件只包含几何，不导出 MTL；材质、光源和变换由场景 JSON 保存。所有文件入口使用 `filesystem::path`，中文及空格路径有单独测试。

## 文件提交

`save_obj` 在目标目录创建独占暂存目录，写完后关闭流，再替换目标目录项。macOS 使用同文件系统的 `filesystem::rename`，Windows 使用 `MoveFileExW` 的替换模式。取消和写出错误均发生在最终提交之前时，原目标文件保持不变。提交开始后不再中断或通过回调抛出取消异常。

进度单位为实际写出的记录，总量为位置数加七倍三角形数：每面三个 UV、三个法线和一个面记录。每 1024 条记录报告一次，最后报告完整记录数；回调前后均检查取消。校验阶段也支持取消。

`save_scene` 先校验文档，再准备资产和 JSON，最后提交 JSON。进度区分数据校验、OBJ 写出、内容哈希、字节比较、资产发布、JSON 写出和最终提交。哈希/比较以字节计数，资产发布以一个文件计数；`commit 0/1` 是最后一个取消点，函数正常返回表示提交完成。

场景目标若与输入网格或纹理路径重合，会在写出前拒绝。检查包含规范路径及文件等价关系，覆盖硬链接与符号链接别名。单独 `save_obj` 只接收网格数据，没有来源路径信息，界面调用方还需阻止用户将几何结果导出到输入资产路径。

失败可能留下尚未被 JSON 引用的新生成资产，原 JSON 和原输入资产仍然保留。暂存目录在退出时清理。两个并发保存各自拥有暂存目录，最终 JSON 来自其中一个完整结果。

## 生成资产

几何操作创建新 `MeshData` 后，其 `MeshAsset.source` 应为空。保存时将生成网格写成 OBJ，再按文件内容生成 `generated-<hash>.obj` 名称，放在场景旁的 `assets` 目录。FNV-1a 仅用于稳定命名，已有同名文件还会完整比较字节。内容相同则复用，内容不同则附加编号，已有文件不会被覆盖。

生成资产优先通过同卷硬链接发布完整暂存文件，不支持硬链接时使用不覆盖复制。暂存目录清理后，资产目录中的文件仍然存在。顺序重复保存同一网格会复用同一内容文件。

已有来源的资产继续转换为相对路径。Windows 跨卷无法产生相对路径时，复制到新场景的 `assets` 目录，同样执行内容比较和冲突换名。来源缺失时报告错误，避免保存出无法重新打开的引用。

函数不修改调用方文档，生成资产在内存中的 `source` 可以继续为空。重新打开场景后，读取器会填入保存的 OBJ 路径。未记录几何操作参数树，保存的是当前生成结果。

## 使用顺序

1. 在 worker 中完成 Loop/位移并验证输出。
2. 在编辑线程的一次事务中创建新网格资产，更新目标物体引用，保留原资产和旧快照。
3. 用户保存场景时，在 worker 中调用 `save_scene`；或调用 `save_obj` 单独导出网格。
4. 任务结束后更新 UI 状态，重新加载时从生成 OBJ 恢复当前几何。

实现分为 `obj_writer`、`asset_writer`、`staged_file` 和原有 `scene_io` 四部分，分别负责文本格式、内容复用/发布、最终提交以及场景序列化。测试位于 `tests/mesh_io_tests.cpp`，覆盖往返、取消、目标保护、内容冲突、并发保存和撤销快照。
