# 光场核心

日期：2026-11-12。A8.1 实现固定瞳孔相机阵列、流式容器、有界缓存、后台采集和重聚焦 CLI。模型、格式和阅读顺序见[光场核心](../LIGHT_FIELD.md)，界面在 A8.2 接入。

## 完成范围

- 3–15 奇数行列阵列、完整瞳孔标定、中心针孔一致性和统一裁剪平面。
- `.mrlf` 小端 RGB32f 容器、严格整数与长度检查、逐视图原子写盘。
- 单视图工作缓冲、有界 LRU、重建工作内存预检和文件存储所有权。
- 共享 PT/BVH 的后台采集、固定快照、进度、预览、暂停恢复和取消。
- 平移叠加、双线性重建、孔径选择、有效覆盖率和独立文件重开。
- CLI、实际近远棋盘、解析平面参考及独立输出比较。

## 核心检查

CPU-only Release 297/297 项通过，ASan/UBSan 297/297 项通过。新增九个光场用例、PT/SPPM 快速切换回归及三个 CLI 检查，原有路径追踪、几何、体积、SPPM、SSS 和任务测试保留。

旋转、平移及非标准 up 相机上的射线和重聚焦偏移与独立射线—平面求交一致。所有瞳孔均遵守同一组 near/far 世界平面。中心子视图与普通、体积和 SSS 场景的既有 PT 逐像素一致。

两个独立正弦平面分别位于 2m 和 8m。重建到正确焦点时恢复解析图案，均方细节能量超过错误焦点的 50 倍。孔径零返回中心视图，常量 HDR 在不同焦距及边界处保持不变。

## 文件与内存

逐视图文件读写保留 RGB32f，包括负值，支持中文与空格路径。最大 uint64 seed 可以完整保存和重开。格式版本、重复视图、尺寸、完整标记、截断、元数据长度和非有限像素均有检查。

写盘或复制回调失败后保留已有目标。捕获器销毁后，结果继续拥有临时存储；最后一个结果引用释放时清理该存储，用户保存的副本保持可读。

64×64、25 视图的数据像素量超过 1MiB，采集在 1MiB 工作预算内完成。逐视图重建的缓存峰值不超过一张视图。该测试同时检查重聚焦前后的采集计数保持不变。过小工作预算在分配图像前被拒绝，并保留原完整结果。

## 暂停协议

快速恢复后立即再次暂停时，原等待者可能仍未离开条件变量。旧光场实现会停留在 pausing，专项回归已复现该问题。

光场已对齐既有 RenderSession 的停稳判定，分别记录 worker 和写盘控制线程的等待状态。光场、PT、SPPM 各通过连续二十次恢复/暂停切换，暂停期间样本数保持不变，取消在 2 秒内终止。原失败记录为 `work/lightfield-pause-repro.log`，最终全量回归均通过。

## 展示场景

近红、远蓝棋盘的物距为 2m、6m，参考焦面为 4m。两块卡片具有相同投影尺寸，均由正向平行光照明。采集设置为 128×128、32 spp、5×5 视图、孔径半径 0.2m、seed=101、深度 1，关闭 RR。

| 像素文件数据 | 4915200 字节 |

清晰度在两个卡片的内部区域，分别用红、蓝通道的水平与垂直梯度绝对值累加测量。近焦、远焦、参考焦距和针孔图像经过检查，数据保存在 `outputs/a8.1`。

4 线程例程与 3 线程 CLI 生成的容器逐字节一致。四种重建的 CLI PNG/EXR 与例程输出也逐字节一致，禁用缓存仍得到相同图像。重建命令只打开光场文件，新射线数为 0，保存的采集主路径数保持不变。

## 复验

```sh
cmake --preset macos-core-release
cmake --build --preset macos-core-release --parallel 4
ctest --preset macos-core-release --output-on-failure
build/macos-core-release/minirender_tests '[lightfield]'
build/macos-core-release/minirender_lightfield_example
```

日志位于 `work/lightfield-core-tests.log`、`lightfield-asan-tests.log`、`lightfield-example.log` 和 `lightfield-cli-*.log`。本阶段使用 CPU CLI，不打开前台窗口。
